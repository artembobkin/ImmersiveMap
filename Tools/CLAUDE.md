# Tools

The XCTest suite reaches a physical iPhone through `Tools/DeviceTests/`. What the project is, what it reads and how it runs is on `Tools/DeviceTests/README.md`, the one place that describes it.

Offline tooling (not part of the SwiftPM build):

- `Tools/TextAtlas/generate_text_atlas.sh`: regenerates the committed MTSDF text atlases in `Sources/ImmersiveMap/Text/Resources/` (`atlas` and `atlas_thin`: RGB carries the MSDF the label fill samples, alpha the plain SDF the halo/stroke coverage is derived from). Requires `msdf-atlas-gen` and local Noto Sans fonts; fonts are never committed. The PNG and its JSON are regenerated together, so a half-updated pair means the shader samples a channel that is not there.
- `Tools/Overview/bake_overview.sh`: bakes the committed overview archive `Sources/ImmersiveMap/Tile/Overview/Resources/overview.pmtiles` (the biomes of RESOLVE Ecoregions 2017 fitted to the Natural Earth coast at zooms 0 to 7, the zoom 0 lakes and the Natural Earth road network at zooms 2 to 5) from the published sources, with the Python steps next to it. Requires mapshaper, tippecanoe and shapely, downloads about 250 MB. The archive is a contract with the built-in style, so a new one bumps `PreparedTileDiskCaching.preparedFormatVersion`.
- `Tools/ReadmeFrames/`: a SwiftPM executable, run through `Tools/ReadmeFrames/render.sh` (which builds it with xcodebuild, since a plain `swift run` leaves the engine's Metal shaders uncompiled and the capture cannot draw), that renders the README's pictures offscreen through `ImmersiveMapStillRecorder`, one AVIF into `Assets/` per frame (2400 pixels wide for a `full` frame, 1600 for a `half` one, written by `avifenc` of libavif, `brew install libavif`, since ImageIO writes a tiled grid that Firefox does not show) of `Tools/ReadmeFrames/frames.json` that has a camera (a camera, an output size, a scene date), with the Develop app's map configuration and tile source, and then writes the README's gallery between `<!-- gallery:start -->` and `<!-- gallery:end -->` from the list in its order, a `full` frame a row of its own and the `half` frames two to a row. A frame may name a `theme` (`night`), carry `avatars` (portraits from a URL or a file, with badges) and `sceneModels` (a USDZ of the repository), all drawn into the capture. A frame without a camera is a picture taken by hand, placed as it is: put its PNG in `Assets/` and run `render.sh --compress`, which turns every frame's PNG there into AVIF and writes the gallery, with no render. The rows between the markers are the tool's: edit `frames.json`, not them. Depends on the engine package by path and is never part of the engine's build.
