# Public API and wiring

`ImmersiveMapView` (SwiftUI, `UI/ImmersiveMapView.swift`) accumulates builder-style modifiers (`.camera`, `.tileURLTemplate`, `.mapStyle`, `.labelSettings`, …) into an `ImmersiveMapSettings` value (`Configuration/`) and wraps the platform host view: `ImmersiveMapUIView` (UIKit) on iOS, `ImmersiveMapNSView` (AppKit, flipped, `CAMetalLayer` backing layer) on macOS - internally unified by the `ImmersiveMapHostView` typealias (`UI/PlatformViewSupport.swift`). The public SwiftUI API is identical on both platforms. Wiring chain: `ImmersiveMapView` → host view → `ImmersiveMapHostRuntime` (shared settings/renderer lifecycle owner) → `ImmersiveMapRuntimeGraph` (composition root, `@MainActor`) → controllers/runtimes + `ImmersiveMapRendererBuilder` → `RenderFrameEngine`. Platform-specific UI (gestures, attribution badge, debug HUD, control zones) lives in per-platform files guarded by `#if canImport(UIKit)` / `#if os(macOS)`; never use `targetEnvironment(macCatalyst)`.

Public controllers: `ImmersiveMapCameraController`, `ImmersiveMapCameraTourController`, `ImmersiveMapAvatarsController`, `ImmersiveMapRoutesController`, `ImmersiveMapSceneModelsController`, `ImmersiveMapSelectionController`, and the two that work with no map view attached, `ImmersiveMapOfflineController` (downloads regions) and `ImmersiveMapStillRecorder` (renders one frame offscreen). The DocC landing page `Sources/ImmersiveMap/ImmersiveMap.docc/ImmersiveMap.md` (what the Swift Package Index renders) is deliberately minimal: an overview paragraph, a snippet and a link to the README; it lists no symbols, DocC collects them from the source, so nothing there needs updating when a public symbol is added. There is no tile-provider abstraction: the tile source is the URL template plus request headers in `TileSettings.NetworkSettings`, set with the `.tileURLTemplate(_:headers:)` modifier, and everything about interpreting the bytes lives on the map style. A map style is two halves. The schema reading in `Schema/` (`ImmersiveMapTileSchema`: one `read` per feature answering with `ImmersiveMapFeatureFacts`, that is road structure, layer, street and kind, building heights, and the label facts: names by language, house numbers, water names) says what a feature is; the style in `Style/` (`ImmersiveMapVectorTileStyle`, answering with `FeatureStyle`) says only how it draws, reading the facts from its context. `ImmersiveMapMapStyle` pairs the two, and `VectorTileMapStyle(style:schema:)` is the generic pairing. The built-in reading is `ImmersiveMapTilesSchema` in `Schema/Default`, the built-in style `ImmersiveMapTilesMapStyle` in `Style/Default` (split by layer family into extensions), and the `ImmersiveMapTilesService` constants for the hosted source are in `Configuration/`. `FeatureStyle` is an enum, one case per drawing mode (`fill`, `line`, `road`, `extrusion`, `pointLabel`, `hidden`), each carrying only its mode's knobs. The engine's geometry work (draw phase, surface ownership, stitching, tunnel roofs, extrusion, the decoration figures) reads the facts and the style and decides nothing of its own: a road's level, tier, class priority, junction making, what its surface does to paint, and every decoration's dimensions are stated on `RoadStyle`; the streetscape switch and the layer's measured crossings reach the style through its context, and the style decides what to draw without them. Styles expose a `configurationFingerprint` (FNV-1a) that drives disk-cache identity together with the source identity (template, base URL, header names), so changing style config must change the fingerprint.
